## Risk Scoring Explanation

Risk scores are deterministic and calculated from signal contributions:

| Signal | Points |
|--------|--------|
| IQC rejected/on-hold/rework/sorting for same supplier+part | +25 |
| Field Defect for same supplier+part | +25 |
| Defect/8D for same supplier+part | +25 |
| Repeat Field Defect or repeated Defect | +20 |
| PPAP approved but later IQC/Field issue | +20 |
| FMEA coverage gap for Field Defect | +20 |
| High FMEA RPN (>=100) for same supplier+part | +15 |
| Open 8D or overdue action | +15 |
| Manual quality link | +10 |

Risk levels:
- **Low**: 0–24
- **Medium**: 25–49
- **High**: 50–74
- **Critical**: 75+

Cap: Maximum 150 points per supplier+part combination.

No AI/LLM is used for scoring. All calculations are deterministic and explainable.

## v2.6.2 Additions

### Risk Signal Edge Cases

1. **PPAP approved-with-issues now verifies date ordering**: Issues (IQC, field defects, defects/8D) must occur on or after the PPAP `approvedAt` date. Pre-approval issues are excluded.
2. **Empty-string partNumber filtered at DB level**: All intelligence queries now filter `partNumber: { not: "" }` and `supplierId: { not: null }` at the database query level, not just at runtime. This prevents:
   - Records with empty part numbers from entering group keys
   - FMEA map entries with empty supplierId/partNumber
   - Unnecessary iteration over invalid records
3. **Defect loop in FMEA coverage gaps now requires supplierId**: Defects without a supplierId are skipped (previously could create signals with `supplierId: null` that would never match any FMEA).
4. **BuildOemHref safety guard**: If an empty/undefined id is passed, returns `"#"` instead of a malformed route.

### Risk Scoring Clarity

1. **Deterministic sort**: Risk table now has a deterministic secondary sort: risk score desc → latest activity desc → supplier name asc → part number asc. Previously only sorted by risk score, which could produce non-deterministic order for equal scores.
2. **NaN/Infinity guard in getRiskLevel**: `getRiskLevel()` now returns `"low"` for `NaN`, `Infinity`, `-Infinity`, or negative scores.
3. **NaN/Infinity guard in computeSupplierPartRisks**: Total score calculation now uses `Number.isFinite()` check before capping.

### Drill-Down Link Safety

1. All `buildOemHref` calls produce only `/quality/oem/...` routes. The intelligence page already gates `companyType !== "OEM"` → redirect.
2. Empty id guard prevents broken links.

### PRO vs Enterprise Gating UX

1. Non-Enterprise upgrade prompt now includes "PPAP post-approval issue detection" and "IQC rejection patterns" in the feature list.
2. Added explanatory text: "Risk scoring is deterministic and explainable — no AI or LLM is used."

### Empty State and UI Polish

1. Risk Intelligence section header now includes helper text explaining deterministic scoring.
2. Risk Table section now shows "Sorted by risk score. Each score is the sum of contributing signal points, capped at 150."
3. Signal panel empty messages now include guidance on when signals appear:
   - PPAP issues: "Signals appear when IQC rejections, field defects, or defect/8D records occur after PPAP approval for the same supplier + part."
   - FMEA gaps: "All field defects and defects with meaningful failure text have matching FMEA failure modes for the same supplier + part."
   - IQC rejections: "Signals appear when inspections result in Rejected, On Hold, Rework Required, or Sorting Required for a supplier + part."
   - Repeat issues: "Clusters appear when 2 or more quality records share the same supplier + part number."
4. RankingTable keys now use `name-index` instead of array index alone.

### Seed Data Verification

- All PPAP-with-issue seed dates verified: post-approval IQC/field/defect dates are after PPAP `approvedAt` dates.
- No seed data changes required for v2.6.2.
