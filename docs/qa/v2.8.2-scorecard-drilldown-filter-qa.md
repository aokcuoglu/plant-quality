## 3. Route Identifier Explanation

### Supplier Company IDs in Seed Data

| Route Slug | Database ID | Supplier Name | Explanation |
|------------|-------------|---------------|-------------|
| `supplier-company` | `supplier-company` | Precision Parts Inc. | Stable seed ID, intentionally simple for demo |
| `supplier-company-2` | `supplier-company-2` | SteelForged Co. | Stable seed ID, intentionally simple for demo |

These are **database Company IDs** set in `prisma/seed.ts` (lines 48–67). They are stable, deterministic, and intentionally human-readable for seed/demo data. The route `/quality/oem/scorecard/[supplierId]` uses the Company ID as the dynamic segment.

**Decision:** These IDs are intentional and documented. No slug migration is performed in v2.8.2. The detail page shows `supplier.supplierName` (e.g. "Precision Parts Inc.", "SteelForged Co.") as the page title, so users see friendly names.

## 6. Expected Query Params

Drill-down links from Supplier Scorecard detail use `supplierId` as the query parameter:

| Source Page | Target Route | Query Param |
|-------------|-------------|-------------|
| Scorecard detail | /quality/oem/field | ?supplierId={companyId} |
| Scorecard detail | /quality/oem/defects | ?supplierId={companyId} |
| Scorecard detail | /quality/oem/iqc | ?supplierId={companyId} |
| Scorecard detail | /quality/oem/ppap | ?supplierId={companyId} |
| Scorecard detail | /quality/oem/fmea | ?supplierId={companyId} |

The `supplierId` value is the Company ID (e.g. `supplier-company`, `supplier-company-2`). It is URL-encoded in links via `encodeURIComponent`.
