# PlantX v3.2.0 — PlantLogistic Production Milestone Tracking QA Checklist

## 1. Purpose

Validate that Production Milestone Tracking in PlantLogistic works correctly, including milestone data model, status workflow, order detail timeline, dashboard summary cards, module entitlement, and tenant isolation. No regression in PlantQuality.

## 7. Status Transition Checks

Valid transitions:
- [ ] NOT_STARTED → PLANNED (shows "Mark Planned" button)
- [ ] PLANNED → IN_PROGRESS (shows "Start" button)
- [ ] IN_PROGRESS → COMPLETED (shows "Complete" button)
- [ ] IN_PROGRESS → BLOCKED (shows "Block" button)
- [ ] IN_PROGRESS → QUALITY_HOLD (shows "Quality Hold" button)
- [ ] BLOCKED → IN_PROGRESS (shows "Start" button)
- [ ] QUALITY_HOLD → IN_PROGRESS (shows "Start" button)
- [ ] PLANNED → CANCELLED (not shown in UI — future)
- [ ] NOT_STARTED → CANCELLED (not shown in UI — future)

## 8. Invalid Transition Checks

- [ ] COMPLETED is terminal — no action buttons shown
- [ ] CANCELLED is terminal — no action buttons shown
- [ ] SKIPPED is terminal — no action buttons shown
- [ ] Server rejects invalid transitions with error message
- [ ] UI only shows valid transition buttons for current status

## 9. Status Transition Side Effects

- [ ] Transition to IN_PROGRESS: sets actualStart if not already set
- [ ] Transition to COMPLETED: sets actualFinish AND actualStart if not already set
- [ ] Transition to QUALITY_HOLD: sets qualityHold = true
- [ ] Transition to IN_PROGRESS from QUALITY_HOLD: clears qualityHold and delayReason
- [ ] Transition to NOT_STARTED: clears actualStart, actualFinish, qualityHold, delayReason
- [ ] Each significant transition creates a timeline event (MILESTONE_STARTED, MILESTONE_COMPLETED, MILESTONE_BLOCKED, MILESTONE_QUALITY_HOLD)

## 10. Tenant Isolation Checks

- [ ] Enterprise OEM cannot see milestones from other companies

- [ ] Milestone actions verify ownership through order.companyId
