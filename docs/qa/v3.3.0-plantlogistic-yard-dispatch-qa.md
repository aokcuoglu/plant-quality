## 6. Dispatch Workflow Checks

### 6.1 Create Dispatch
- [ ] "Add Dispatch" button creates a new dispatch record
- [ ] Form fields: Batch No, Carrier Name, Transport Mode, Destination Country/City, Dealer/Distributor, Tracking Ref, Planned Loading Date, Estimated Arrival, Notes
- [ ] New dispatch has status NOT_PLANNED
- [ ] DISPATCH_CREATED event appears in timeline

### 6.2 Edit Dispatch
- [ ] Edit button on dispatch allows updating all fields
- [ ] Saved changes persist and display correctly

### 6.3 Status Transitions
- [ ] NOT_PLANNED → PLANNED (via status transition button)
- [ ] PLANNED → CARRIER_ASSIGNED
- [ ] CARRIER_ASSIGNED → LOADING_PLANNED
- [ ] LOADING_PLANNED → LOADED (sets actualLoadingDate)
- [ ] LOADED → IN_TRANSIT
- [ ] IN_TRANSIT → ARRIVED (sets actualArrivalDate)
- [ ] ARRIVED → DELIVERED (sets deliveredAt)
- [ ] NOT_PLANNED / PLANNED / CARRIER_ASSIGNED / LOADING_PLANNED → CANCELLED

### 6.4 Invalid Transitions
- [ ] DELIVERED and CANCELLED are terminal — no transition buttons shown
- [ ] Skipping status (e.g., NOT_PLANNED → LOADED) returns error from server
- [ ] Status change creates appropriate timeline event

### 6.5 Dispatch Status Badge
- [ ] Each dispatch status has a distinct badge color
- [ ] NOT_PLANNED: muted
- [ ] IN_TRANSIT: amber
- [ ] DELIVERED: emerald
- [ ] CANCELLED: destructive

### 6.6 ETA Risk
- [ ] If estimatedArrivalDate is past and status is not DELIVERED/CANCELLED, ETA shows amber
